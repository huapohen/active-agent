## 2. 核心行为验收

| 场景 | 验证方式 | 观察结果 |
|---|---|---|
| 编辑连续发生 | 可控时钟的 worker 测试 | 安静窗口重置，到期前不请求模型 |
| 任务暂停 | worker 与真实 API 测试 | 不评估；旧在途结果不能发布 |
| 同版本重复投递 | 并发发布到真实服务器 | 一份可见提案，另一次命中 duplicate |
| 过期正文/任务 | API 与 CRDT 比较 | 409 或 conflicted，保留新正文 |
| 文字相同、CRDT 状态变化 | 独立 CRDT 事务 | 提案也会失效 |
| 人工接受/拒绝 | 真实 API 和浏览器 | 接受更新正文；拒绝不改变正文 |
| 非真实原文引用 | 校验测试 | 拒绝伪造 evidence |
| worker 数据库丢失 | 新 checkpoint 文件重建 | 从已发布文档恢复，避免重复模型调用 |
| 两个 worker 共用 checkpoint | 租约测试 | 未持有租约的实例不执行 |
| 模型失败 | 退避测试 | 三次失败后停止自动模型尝试 |
| Responses 中断或畸形数据 | SSE 单元测试 | 不提交部分文本 |
| 服务进程重启 | 真实服务器重启 | 文档、提案与事件游标保留 |
| 正文提交后、提案收尾前中断 | CRDT 回执恢复测试 | 收尾为 accepted，不重复写正文 |
| REST / MCP 一致 | MCP 创建、REST 读取 | 同一文档，中文 actor 正常保存 |

## 3. 真实大模型实验

模型：`gpt-6-astra`；思考强度：`medium`；配置仅在本机忽略文件中。请求发送到用户指定的临时兼容网关，本报告不复制该服务的凭据。

首先验证模型列表包含指定模型。Chat Completions 请求返回网关的通道不支持错误。随后使用 Responses SSE，确认完整 `output_text.done` 和 `response.completed`。网关的 completed 包中 output 为空，适配器从已结束的文本条目恢复完整输出。

完整 UI 任务于本机 **2026-09-06 02:27–02:33（UTC+8）** 执行：

- 来源：自动创建的“上线计划 · 一次共同推进”。
- 目标：只把“验收条件”一节的三条模糊要求变成可验证条件，保留其他章节。
- 模型返回：`propose`，包含两个真实原文引用；明确说明条件是待验证建议，没有声称执行过测试。
- 工作台显示完整理由、引用和修改前后内容。
- 在浏览器接受后，来源从 `r1` 到 `r2`，记录审阅人“文档协作者”。
- 核对结果：目标、已确定边界、下一步与保留约束章节保持不变。

这是一次真实成功案例，不是多模型、多任务的统计质量基准。调用计费以服务商记录为准，本轮没有据此推算单位成本或成功率。

## 4. 浏览器检查

- 桌面：1512 × 982，检查登录、示例创建、实时编辑器、任务卡、提案证据和接受流程。
- 中文姓名：修复 HTTP header 不支持非 Latin-1 字符的问题，采用编码后的 actor 标签。
- 双客户端：两页连接同一 Yjs 文档，分别在两个独立位置同时写入原子文本，最后两个客户端内容一致且两份新增文本均保留。

- 浏览器控制台：最终检查无 error / warning。

## 5. 当前不能承诺的能力

| 边界 | 当前状态 | 上线前应补充 |
|---|---|---|
| 细粒度权限 | 共享工作空间令牌 | 独立身份、文档 ACL、令牌撤销 |
| 人工审批不可伪造 | actor 是可声明标签 | 可信身份和审批主体校验 |
| 文档富内容无损 | 文本/标题路径优先 | 表格、图片、标记、列表、附件往返测试 |
| 字符级并发体验 | 有两端收敛证据 | 大量客户端、不同选区、IME 专项测试 |
| 长时间/大规模稳定性 | 本机短时验证 | 24h+ endurance、负载、压缩、灾备 |
| 横向扩容 | 单进程服务/本机共享租约 | 共享事务存储、跨实例锁、worker 队列 |
| 事件保留与性能 | 全量读取，日志未压缩 | 增量订阅、保留策略、重建协议 |
| 自动执行外部工作 | 没有外部执行工具 | 独立的能力范围、授权和验证机制 |
| 任意模型可靠性 | 指定网关单案例 + 协议测试 | 可重放、多 provider 的公开评测集 |

## 6. 安全与开放边界

新的模型 worker 没有 shell、浏览器、IM、邮件、发布或交易工具。来源文档作为不可信数据交给模型；输出仍需结构校验、原文引用校验和人工审阅。引用存在不代表建议正确，提示词隔离也不能证明彻底解决注入问题。

共享令牌可以调用审阅接口；内置 worker 不自动接受提案，但整个系统尚无强制的人/Agent 权限分离。旧版通用文档工具并不是不可变审计边界。仅在可信、自托管环境中使用当前预览。

首次导入 active-agent 前已清除旧 `.env.example` 中的凭据；Git 忽略模型配置、数据库、运行日志和浏览器状态，Docker 构建上下文也排除本机秘密文件。发布前扫描的是实际暂存内容。该扫描是必要检查，不是不存在任何秘密的数学证明。
