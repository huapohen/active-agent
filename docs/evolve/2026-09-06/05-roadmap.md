## 1. 目标的正确拆解

100k stars 代表广泛认知与持续认可，无法由一次代码提交保证。当前先建立可展示、可复现、可贡献的差异化：**人写文档时，Agent 能持续参与；每次介入都能被解释和审阅。**

下面是后续路线，不是本轮已完成清单，也不是对时间或增长的承诺。

## 2. 0.2：可运行闭环（本轮）

- 真实在线文档 + 持续目标 + 自动观察 + 带依据的提案 + 接受/拒绝。
- 冲突保护、重复抑制、服务重启与提交回执恢复。
- 可见契约、REST/MCP、两个模型协议。
- 一条启动命令，双语首页，真实截图，MIT 许可证，CI 和带 commit 的详细文档。

质量门槛：贡献者能按 README 启动、通过本地测试、解释一次提案的完整来源；没有把临时模型凭据放进仓库。

## 3. 0.3：把文档体验做好

优先级从最高开始：

1. **单一富文档模型**：确定 Markdown/ProseMirror/Yjs 映射；为格式、列表、表格和附件做无损往返样例，禁止默默降级。
2. **局部提案与局部接受**：提案锚定稳定块，展示实际 diff；人在正文边上处理建议，减少整篇对照的阅读负担。
3. **精确编辑意图**：人在任务文档中声明可修改章节、不可改变约束、何时必须提问；协议强校验作用范围。
4. **反馈连续性**：拒绝时写入原因；Agent 下一轮能够明确引用反馈，避免重复同一建议。
5. **身份与协作存在感**：人、Agent、服务有独立主体与可撤销授权；在线状态不仅是展示名称。

建议验收：至少 50 个公开、可重放文档场景；每一个模型产出都能追溯到精确来源版本；并发保护与部分失败样例全部通过。目标值是发布门槛建议，当前没有这些统计成绩。

## 4. 0.4：让主动性成为可靠能力

- 从全量轮询迁移到 CRDT 变更订阅 + 可重放事件，断线后用游标恢复。
- 将安静窗口升级为显式“正在写作 / 一段完成 / 可介入”的协作协议，允许人表达意图。
- 为每个任务配置模型调用次数、时间、token 预算与重试上限，所有耗用回写可见运行记录。
- 评估无关干预、重复建议和错误完成宣称，不只评估生成文本质量。
- 在明确、狭窄且可回滚的文档范围中实验用户预授权自动应用；权限和补偿机制应先于默认打开。

建议指标：首次有用提案耗时、采纳率、重复干预率、冲突时的数据保全率、每次有用改动的调用成本。公开测量方法和原始样例，不展示无法复现的数字。

## 5. 1.0：可信团队基础设施

- 文档级 ACL、SSO/OIDC、团队身份、审批主体、审计导出。
- 可迁移持久化、备份恢复、文档/附件导出、事件保留和回放契约。
- 跨实例调度、租约续期、资源配额、服务可观测性。
- Linux/macOS 和主流浏览器兼容矩阵；部署指引与演练记录。
- 在持续负载下验证协作收敛、预算和故障恢复，才给出明确服务能力边界。

IM 继续是独立产品线，不把接入 IM 当作完成上述基础工作的捷径。

## 6. 开源呈现与社区

| 阶段 | 具体动作 | 判断是否有用 |
|---|---|---|
| 首次访问 | 双语 README、真实界面、90 秒可复现演示 | 读者理解“文档里持续工作的 Agent” |
| 首次安装 | 一条组合启动命令、诊断清单 | 能在自己的环境拿到首个提案 |
| 首次贡献 | 小范围问题、测试 fixture、协议文档 | 不熟悉原作者也能定位代码 |
| 持续协作 | 日期/commit/验证结果完整的发行记录 | 每个版本的能力与风险可追溯 |
| 长期信任 | 公开评测、及时修复、明确兼容边界 | 演示与真实使用表现一致 |

维护者应优先接收真实失败用例、协作 UX 问题和可以重现的 provider 差异。不要把短期 star 数、Agent 数或工具数当作产品质量替代物。
