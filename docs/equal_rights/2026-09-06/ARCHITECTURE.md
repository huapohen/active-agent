# 人机同权、文档载体与原生协议

## 共同工作现场

Flutter 是人和 Agent 都能登录的同一客户端。后台 Agent 通过独立 bearer 身份调用同一成员 API/MCP，主动订阅事件、进入会话、发送 @、读写共同文档、领取任务和参加会议。不会用作者字段伪造身份，也不要求 Agent 模拟鼠标键盘。

`human` 和 `agent` 是身份类型，不是权限级别。业务权限来自会话成员资格、所有者角色和文件/文档归属。Agent 可以是会话所有者，人也可能只是成员。Agent 商店安装的是独立同事身份；普通客户端拿不到管理凭据或别人的 worker token。

## 文档是载体

共同依据是可读取的 Doc Free 正文与版本、任务描述、会议纪要和显式运行记录。每次模型运行前，服务器保存当轮消息、参与者、文档版本与内容、任务、输入指令、模型配置、预算及遗漏清单；输出草稿与简明依据可审阅、可导出。

运行时仍需内存、索引、JSON 保存与媒体队列。它们负责传输和持久化，不构成 Agent 独占的工作记忆。SDP/ICE、设备状态属于短期传输数据，不写入长期工作文档或模型上下文。文档编辑以 base_revision 检查并发修改；冲突保留草稿、读取最新版并明确合并。

## 服务边界

- Active Agent Python：身份级 worker/fleet、模型调用、重试与可见阻塞；开发启动器管理隔离端口与本机凭据。
- Doc Free Node：独立身份、房间、消息、共享文档/任务、成员权限、事件、租约、Agent 商店、日程、会议与附件。
- Flutter：macOS、Windows、iOS、Android、Web 共用状态层和页面；同一请求能力不按人/Agent 分叉。
- 原生 MCP：`POST /api/im/mcp`，工具直接复用成员端点，不暴露管理员工具。

## 重试、撤权和一致性

消息和重要创建操作使用身份/房间绑定的 client_id；网络响应丢失后的同一意图重试不会重复创建。事件游标可以重连；读取时再次验证当前成员资格。移除成员、撤销身份、暂停 Agent 会取消执行中的工作租约。finish 检查消息、文档、任务及成员版本，过期输出不能覆盖新工作现场。

JSON 持久化通过临时文件、fsync、rename 完成，失败后服务停止接受写入，避免展示未落盘的成功。仍是单 Node 进程模型，没有分布式写锁。Doc Free 文档创建与房间绑定跨两套保存，中断可能产生管理员可见孤立文档，需要核对后导入恢复。

## 实际 Agent 自动化范围

所有办公 API 可由具备身份的 Agent 直接使用，包括主动消息、任务、文档、日程和会议。当前内置模型 worker 的自动执行合同仍以回复、阻塞与文档草稿为主；通用工具规划和多步办公执行器尚未接入这一默认 worker。协议能力、后台自动化能力和 UI 功能分别验收，不把可调用 API 等同于模型已能可靠自主执行任意工作。

## 媒体与部署

首版使用最多六个媒体会话的 WebRTC mesh。加入默认不访问麦克风或摄像头；用户启用后才请求设备。房间会员和短期 session 共同约束信令。离开、结束、撤权、45 秒 TTL 或服务器重启后需要重新加入。公网穿透需要运营方配置 STUN/TURN，不能以本机直连验收宣称大型企业会议容量。

凭据只在运行期内存或忽略的本机配置。发行客户端不含 `.env`、模型 Key、测试身份或业务数据。生产还需 SSO、多租户、推送、审计运营、签名发布、备份恢复和规模测试。
