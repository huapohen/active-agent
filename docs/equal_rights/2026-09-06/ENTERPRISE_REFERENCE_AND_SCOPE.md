飞书确有机器人、智能伙伴和“应用身份权限”，页面明确说明应用可在用户未登录时自动执行操作。差异目标应准确表述：我们的 Agent 是可独立登录同一 UI、拥有企业角色和个人业务对象的成员，其原生接口不依赖点击；不能以“飞书完全没有自动接口或机器人”作为技术前提。

## 三端身份差异

- Chrome：管理员身份可进入管理后台，已逐页检查上述页面。
- 桌面：左下角切换公司，头像菜单的管理员身份包含“管理后台”；点击后在 Chrome 打开对应企业 Web 管理后台。员工身份头像菜单没有该入口。只隐藏菜单不是服务端权限证明，因此自家另做直接 API 与已有会话降权测试。
- iPhone：早前已观察公司IM、工作台、会议、文档、全局+与群@面板。本轮企业管理入口检查时镜像显示 `Connection Interrupted`，已请用户恢复。尚未验证的手机后台流程不能标为“已复刻”。

## 原生权限合同

一个部署对应一个工作空间。企业角色独立于房间所有者和Agent的商店安装者；现存身份只迁移为普通member。初始owner通过部署级bootstrap凭据显式指定一次。后续角色更改只走企业成员权限，重启不恢复旧角色。当前没有多租户、跨企业身份切换或企业SSO实现。

`GET /enterprise` 可读取自己的角色及实际能力。企业管理路径要求当前owner/admin；普通成员直连返回403。admin管理普通成员和部门，owner管理高级角色与企业资料。人或Agent遵循相同条件。禁用使机器身份和账号会话失效、打断长轮询、取消运行；最后一位有效owner不能被降权、禁用或撤销。

企业应用策略与个人插件偏好分离。策略禁止的模块在REST/MCP/A2A被拦截，聚合搜索、库、事件、房间详情和历史回执也要按当前授权过滤或拒绝。设置、身份与企业管理入口保持可访问以恢复配置。各模块仍有自己的业务权限；企业管理员不会因此获得任意私人邮箱或非成员房间正文。

会议首版依赖会议、日历、文档三个模块；完整房间导出及Agent混合上下文需要消息、文档、任务、会议、日历。已发表到聊天的正文属于消息历史，不因原始来源模块之后关闭而追溯删除。扩展插件登记仍表示“未连接”，不是已执行硬件或外部软件操作。

## 文档载体与可验证范围

组织和审计可以导出为可读Markdown；每个操作仍保存版本、行为主体和时间。UI与协议使用同一真实状态，不能将概念方案、静态按钮、构建成功或第一阶段旧安装包作为全功能完成证据。

默认模型worker现阶段仍以回复、可见阻塞和文档草稿为主。外部Agent可原生调用办公及管理协议；让默认worker可靠自主执行一组业务动作还需冻结计划、逐动作权限/租约校验、原子回执和重启恢复。具体设计见 [原生动作执行设计](NATIVE_ACTION_EXECUTION_DESIGN.md)，该文明确标记待实现。

## 后续实看：企业即时消息设置

实际进入了群规模管控、群权限管控、消息权限管控。群规模区分对话群与话题群、人数上限及补充规则；群权限包括公开群搜索加入、是否允许退出部门群、成员信息导出范围；消息权限包括是否允许编辑/撤回及24小时等时限、应用代发消息的标识展示位置。自家已有消息作者归属、成员ACL、编辑/撤回和版本控制，但这些企业级细粒度规则尚未全部实现，不能将模块开关当成上述全部规则。
