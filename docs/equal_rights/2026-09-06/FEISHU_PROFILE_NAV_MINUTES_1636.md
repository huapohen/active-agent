## 1. 头像是独立的个人入口

### Mac：锚定头像的菜单

在本次约 **1009×756** 的窗口截图坐标系内，最左应用导航约 180 像素宽。左上圆头像与创建按钮并列，下方是统一搜索；头像不是工作台应用图标。

点击“我的头像”后，在头像右下打开白底、有阴影的圆角浮层。浮层宽约 **318** 像素，员工身份高度约 **444**，管理员身份约 **500**。这些是当前截图的近似视觉测量，不是飞书设计系统的逻辑像素或规范值。

| 区域 | 本轮实际可见结构 |
| --- | --- |
| 身份区 | 约 56 像素圆头像、姓名与编辑图标、企业小字、认证标记、状态入口 |
| 简介区 | 浅灰底的一行个性签名提示 |
| 个人菜单 | 我的个人名片、我的二维码与链接、登录更多账号 |
| 第二组 | 分割线后帮助与客服、订阅入口、设置、退出登录 |
| 管理员附加组 | 再一条分割线后“管理后台”，右侧为外部打开图标 |

本轮实际切换了两个已登录企业身份。自有企业管理员的浮层有“管理后台”；员工企业身份没有这一行。两者均保留个人“设置”。管理入口是权限相关的附加入口，不应该把管理员的个人设置替换为企业管理。

桌面已登录身份切换位于应用导航最底部的一排小身份图标，另有登录更多账号入口。切换会改变头像颜色、企业上下文及可见导航内容，不能仅替换标题。

### iPhone：双栏侧抽屉

本轮重新查看的是员工身份。镜像截图约 **319×703**；头像抽屉占约 270 像素宽，右侧留出约 40 像素灰色遮罩。左侧约 75 像素为身份栏，当前身份旁有蓝色竖线；右侧约 190 像素为个人内容。这些比例只用于说明层级，实际实现须适配设备安全区和文字缩放。

个人区顶部有圆头像、姓名、企业小字/认证标记、右上“+ 状态”，接着是个性签名。下方为图标加文字的纵向行，约 43 像素行距：个人名片、钱包、收藏、登录更多账号、帮助与客服、订阅、登录设备、设置。登录设备行可在右侧显示设备数。

员工抽屉没有企业管理。本轮没有再次切换手机管理员身份；此前手机管理员抽屉新增“企业管理”的证据见 15:30 记录。不能把此前观察写成 16:36 新执行的验证。

## 2. 设置的电脑与手机布局

### Mac：保留应用框架，在内容区中打开设置

点击头像菜单的“设置”，最左应用导航仍在。设置内容区顶部为标题和右上关闭图标，内部左侧约 240 像素的分类栏、右侧滚动正文。个人账号区可见账号概览和账号安全中心入口；通用区有带预览的浅色/深色模式等设置。

本轮可见分类包括账号与安全、通用、隐私、效率、通知、快捷键、文档、日历、邮箱、视频会议、任务、系统诊断、实验室、更新、关于；特定企业版本还有自己的分类。右侧长表单会异步加载内容，首次树快照不一定是最终状态。本轮没有调整任何开关、账号、通知或系统配置。

### iPhone：全屏分组列表，二级页逐层返回

“设置”进入全屏页面：顶部居中标题，左侧返回，浅灰背景，分组白色圆角卡片，行高约 38–40 像素，右侧箭头表示二级页。

第一组为账号安全中心和通用；通知单独成组，若系统未启用通知，右侧有橙色提示与前往开启入口，下方有解释文字。应用设置为另一个组，含隐私、日历、邮箱、视频会议、任务、效率。其后为数据清单、内部设置和实验室等。

实际打开“通用”二级页，可见外观、会话显示模式、显示语言、名片页姓名展示、内容翻译、字体大小、24 小时制、网络诊断、缓存清理。普通选项使用右箭头和当前值，布尔项直接放开关。返回后恢复上级设置页面，再返回主框架。本轮没有打开系统通知设置，也没有清理缓存。

## 3. 手机“更多”与底栏编辑

本次员工主界面底栏有五个业务模块和最右“更多”。业务模块受当前企业配置影响，不能视为所有企业固定一致。

点击“更多”，出现约占屏高七成的底部面板，背景变暗、顶部有拖柄。面板内部顺序为：

1. “最近使用”标题，右侧“全部”，下面为纵向应用行。
2. “更多”标题，右侧蓝色“编辑”。
3. 四列图标网格，展示没有固定在底部的应用。

点击“编辑”后，进入全屏“更多”编辑态：右上为蓝色“完成”，上方四列排列可选应用；屏幕底部白色圆角槽显示当前五个业务导航项，更多自身不在这五项之中。没有看到 checkbox 或行内开关，也没有看到显式操作说明。

本轮只观察编辑态，没有点击应用、拖动应用或保存配置。因此只能确认页面布局和入口，不能声称已经实际验证拖动跨区、固定上限、顺序保存或跨设备同步行为。尝试从空白区左缘返回没有离开编辑页；为遵守本轮不保存飞书配置的边界，未点击“完成”。观察结束时手机仍停在未修改的编辑页。

本项目可采用明确的选择、排序与保存交互，只要真实保存的是当前身份的导航偏好，并始终提供“更多”入口。不要因为飞书有配置项就渲染没有真实行为的装饰性开关。主导航、工作台收藏、个人设置、企业应用授权应保留各自清楚的用途。

## 4. 妙记与智能纪要是两个并列入口

在本轮自有企业的“视频会议”页面，妙记和智能纪要以并列 tile 出现。页面还有发起/加入/预约会议、投屏等入口；“入会时同步开启录音转写”是单独启用卡，右侧另有线下内容上传与录音卡。本轮没有点击开启、发起会议或录音。

### 妙记：音视频和转写内容库

员工企业可从应用导航直接进入妙记；自有企业从“视频会议 → 妙记”进入。两种入口均保留主应用框架。

妙记内部左栏为主页、我的内容、共享内容、回收站。顶部有搜索，页面右侧有录音和上传；本次员工版本还能看到 AI 问答入口，自有企业版本可见个人热词入口。列表结构包括缩略图、标题、时长、所有者、创建/共享时间和更多操作；可按归属与时间筛选。列表行约 100 像素高，音频使用占位封面，视频可能有预览缩略图。本轮只观察行结构，没有打开任何已有私人录音、视频或转写。

自有企业没有妙记文件，显示插画和“暂无妙记文件”空态。这一空态给本项目无数据时的入口设计提供了可确认参考。

“上传”是下拉菜单，实际可见“上传本地文件”和“导入企业云端文件”。打开本地上传后是约 **600×350** 的居中对话框：

- 标题“上传音视频文件”，有隐私说明及链接。
- 中间虚线拖放区，支持拖入文件或选择文件。
- 下方“自动识别语言”复选框，观察时默认为选中。
- 底部取消、提交；未选择文件时提交禁用，右上也有关闭图标。

本轮未选择文件、未切换语言选项，点击取消并确认对话框消失。没有实际上传或转写，也未观察录音进行中的界面。

### 智能纪要：云文档式纪要库

“视频会议 → 智能纪要”打开独立的云文档纪要库，路由形态为 `/drive/ai-notes/`，而妙记为 `/minutes/` 系列。它不只是把音视频列表换一个名称。

顶部标题和返回按钮、右上设置；下方 tabs 为“归我所有”“我参与的”“与我共享”，右侧筛选。表格列为标题、所有者、修改时间、创建时间，创建时间可排序。

实际打开筛选弹层及类型下拉，可见“会议纪要”“每周会议速递”“上传/录音纪要”。本轮没有选择或保存筛选项。自有企业为空，显示“当前无会议纪要，可在会议中开启智能总结”和发起会议按钮；没有点击发起会议。

因此目前可以确认的是内容来源、归属与文档库的导航层级。纪要正文、说话人分段、时间戳播放、转写编辑和 AI 问答详情未在本轮查看，不以推测补成“实测”。

## 5. 对人机本轮实现的建议与验收边界

本节是基于观察的建议，最终实现和测试结果由本项目相应提交记录证明。

| 目标 | 本轮建议 | 应验证的真实行为 |
| --- | --- | --- |
| 头像个人入口 | 桌面锚定菜单，手机侧抽屉；身份概览、设置、会话退出；企业管理按权限显示 | 当前身份正确；普通成员没有管理入口且服务端仍拒绝越权 |
| 设置 | 手机分组列表，桌面分类与正文 | 已提供的偏好真实保存；退出后重新登录不混用其他身份偏好 |
| 导航编辑 | “更多”内提供入口，选择与排序可被理解 | 固定数量规则清楚、保存/取消正确、当前已打开模块不会变成死路 |
| 纪要库 | 先提供已有文档能力支持的文字纪要，与会议和可见来源关联 | 新建/编辑/重新打开、来源定位、权限校验可实际完成 |
| 纪要到待办 | 纪要内确认决策与行动项，关联真实任务、负责人和状态 | 创建任务后能跳转和复核，不把模型文本当成已执行回执 |
| Agent 协作 | 人和 Agent 使用同一可见来源、纪要文档与任务对象 | Agent 的输入依据、改动和执行结果可被成员查看，仍受现有权限约束 |
| 音视频扩展 | 等真正接通采集/上传/ASR 后再启用录音转写 | 不把文字摘要界面标记为已完成音视频转写 |

本轮已将头像菜单、移动设置层级、底栏编辑和两类纪要库的观察分批同步给前端与主执行者。没有更改项目核心服务、没有操作用户的本地人机调试服务，没有保存飞书配置、发送消息、发起会议或采集音视频。桌面结束于自有企业智能纪要空态与筛选菜单，手机结束于无改动的导航编辑态。
