## Pin 与顶部置顶分开

既有 Pin 是多项消息集合；新增会话顶部置顶是独立的共享资源。本批最多展示一条共享顶部置顶，Pin 不会自动替换它，取消顶部置顶也不会删除 Pin。

| 动作 | 原生接口 | 关键行为 |
| --- | --- | --- |
| 读取顶部置顶 | `GET /rooms/:rid/highlights` | 返回当前来源视图、共享版本和本人的收起状态 |
| 设置、替换、清除 | `PATCH /rooms/:rid/highlights` | 核对共享 revision 与来源消息 revision，冲突要求刷新 |
| 本人收起、展开 | `PATCH /rooms/:rid/highlights/preferences` | 仅影响当前身份所见版本，不改其他成员状态 |
| 原 Pin 集合 | `/rooms/:rid/pins` 与消息 `/pin` | 保持独立 |

桌面使用对话框，手机使用可关闭底部面板；会话顶部有两行正文预览、查看原消息和管理入口，经典表情沿用统一渲染。来源编辑显示当前正文与变化提示，撤回、个人隐藏及失权场景不保留不可见的旧正文。共享置顶更新后，新版本重新展开，不继承用户对旧版本的收起。

管理权限采用服务端当前会话成员资格，Human 与 Agent 一致；企业管理员身份不能代替会话授权。飞书实际菜单已确认 Pin 与“置顶消息”是两个条目，但其置顶深层配置、槽位数量及全部权限规则尚未逐项实测，本批明确的单槽规则不是对飞书内部实现的断言。

## 应用内加急：真实成员、未读证据与显式确认

飞书桌面配置页已实际打开并取消，观察到搜索、成员复选框、“全选未读成员”、已选人数、三种发送方式、取消和带 `⌘+Enter` 提示的发送入口。没有向真实飞书同事发送加急或消息。

人机发起页从原消息与当前群成员加载真实接收人，Human 和 Agent 在同一列表内可搜索、多选。当前只允许消息作者为自己的来源发起，不能选本人、已退出成员或伪造全局联系人；每次最多 100 位接收人。

“全选未读成员”读取消息 readers 的显式阅读快照，只自动加入有确定 `unread` 证据、仍为当前成员、且属于原成员周期的目标。未知已读状态、旧消息无证据、退出后重新加入、发送后新加入和不在当前名单内的身份，不自动归为未读。读取失败会显示原因和重试入口，不伪造选择。

发送方式保留三项结构：仅应用内、应用内加短信、应用内加电话。本批只有 `in_app` 真正可发送；短信和电话显示渠道未配置并禁用。按钮、`⌘+Enter` 和 `Ctrl+Enter` 共用同一提交守卫，不能绕过选人、离线、发送中或来源变更检查。

| 动作 | 原生接口 |
| --- | --- |
| 创建请求 | `POST /rooms/:rid/messages/:mid/urgencies` |
| 收到、发出、全部列表 | `GET /rooms/:rid/urgencies` |
| 当前授权详情 | `GET /rooms/:rid/urgencies/:uid` |
| 本人明确确认 | `POST /rooms/:rid/urgencies/:uid/ack`，空对象 body |

创建前核对实际来源版本与目标成员。首次请求使用稳定 client_id；回包不明时保存原发送意图，重试不生成新的请求身份。若来源或成员随后改变，后端仍先做当前授权检查，可能返回 409/422，UI 停止自动重建并要求核对已发送记录。应用重启后的发送意图持久化恢复和按 client_id 单独查询回执尚未完成。

打开详情只读取，不能自动确认。“我已知晓”只向服务端确认当前登录者自己，不能传另一个人的身份代签。消息阅读 ACK 与加急确认是两份状态：读过消息、打开加急、Agent 领取工作或结束一次运行，都不会等同于加急确认。

发送者能看全部已选接收人的确认；接收者只看自己的记录与计数。来源隐藏、撤回、变更、缺失、创建者失效或成员周期改变，均按服务端状态限制读取和确认。列表分页失权时清空之前缓存的私有条目；详情失权不保留旧正文或旧名单。

## Agent 原生入口与主动性

顶部置顶、加急及确认提供 REST、MCP 和 A2A 入口，使用同一身份、会话授权和应用策略。新增 MCP 工具为 `im_highlights`、`im_set_highlight`、`im_collapse_highlight`、`im_urge_message`、`im_urgencies`、`im_read_urgency` 和 `im_acknowledge_urgency`。

被指定的 Agent 可以把加急作为原生工作触发；`mentions` 模式可以响应，`paused` 模式不领取。多条待处理请求分别领取，已处理的 root 不因尚未确认而无限重复。执行上下文包含被加急的实际来源，即使该消息早已超出最近 40 条消息。

每个目标的触发运行保持私有范围，不能通过清单、事件、turn、运行导出或旧 A2A 回执枚举其他目标。后续由 Agent 明确产出的共享消息、任务或文档仍按正常会话规则可见。

本批协议测试使用可验证执行器，没有调用真实大模型；不能把“触发链与权限测试通过”写成“生产模型已经可靠完成自主工作”。

## UI 状态与导航边界

- 工作身份、endpoint、principal 或 room 作用域改变后，旧组件失效；迟到回包不能恢复旧正文或把旧请求结果写到新身份。
- 置顶、加急详情及分页请求得到 403/404 后清除私有缓存，确认按钮与旧数据一起失效。
- 其他 ModalRoute 覆盖会话时，停止消息阅读 ACK，避免用户实际正在看弹窗时把后面消息记为已读。这项是消息阅读保护，不自动确认加急。
- 房间详情跳转必须仍 mounted、身份有效且所在 route 当前可见，并在 pop 前消费一次性守卫。实际 Navigator 回归覆盖：上层临时页面不被旧回调关闭、同帧两次回调只执行一次、后继搜索面板不被误 pop、详情 dispose 后保留的回调无效。

房间详情专项 11/11 通过。新增回归在修复前已实际失败，修复后通过，检查包含后继页面的真实 pop 次数与正常返回首页。
