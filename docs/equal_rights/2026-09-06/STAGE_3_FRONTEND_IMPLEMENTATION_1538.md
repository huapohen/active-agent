## 1. 办公入口中的职业 Agent 同事

Agent 商店读取服务器返回的职业目录，以真实返回条目计算数量。客户端没有把“100”写成固定展示数字，也不会为 100 个模板各启动一个模型。安装操作调用已有真实安装接口，将模板变成工作空间可加入会话的 Agent 身份。

目录支持名称、职业、职位、组织、部门、技能、标签及说明搜索；分类、职业、来源组织是独立筛选条件。条目展示工作约定，可展开查看实际 instructions。没有职业信息的旧模板保留可用，不补造职位、公司或能力。

字段语义：

| 场景 / 字段 | 展示含义 |
| --- | --- |
| 商店模板 `organization_name` | 来源组织 |
| 已安装成员 `organization_name` | 当前任职组织 |
| 已安装成员 `source_organization_name` | 商店模板来源 |
| `profession` / `job_title` | 职业 / 职位 |
| 模板 `department_name` | 来源部门 |
| 企业成员 `department_name` | 当前部门 |

同一个 Agent 可以来源于某职业目录，任职于当前企业的组织。来源不会自动变成企业成员资格，也不赋予管理员权限。人类与 Agent 仍使用同一 principal 与服务端授权体系。

主要实现：`agent_catalog.dart`、`professional_identity.dart`、`people.dart`。

## 2. 企业组织和成员工作资料

有 `manage_organizations` 能力的成员可以读取、新建、重命名和删除空组织。删除入口在非空组织上禁用，服务器继续检查实际成员数量。修改和删除携带 `base_revision`，冲突时保留本地输入，明确读取新版本之后才能重新提交。

成员新建与编辑包含职业、职位和当前任职组织。未指定独立组织时，使用工作空间默认企业。管理员编辑自己时仍保留原有“只允许改姓名”的自编辑限制，新增字段不会绕过该规则。

相关协议：

```text
GET    /api/im/enterprise/admin/organizations
POST   /api/im/enterprise/admin/organizations
PATCH  /api/im/enterprise/admin/organizations/:id
DELETE /api/im/enterprise/admin/organizations/:id
```

当前组织是**同一工作空间的组织目录**，不表示已经实现多租户隔离。角色仍是当前真实支持的 owner/admin/member 与能力集合；不宣称拥有飞书的资源级管理角色矩阵、风险控制、无权限引导或完整管理员审批体系。

390px 手机页面采用独立企业管理首页与分组入口：企业资料、通讯录/组织、权限与应用。成员、部门、组织、角色、应用、审计、Markdown 导出均导向已有操作；子页面可返回企业管理首页。界面没有虚构企业认证、客服或无后端支撑的管理入口。

主要实现：`enterprise_state.dart`、`enterprise.dart`、`enterprise_organizations.dart`。

## 3. 配置式企业登录

登录页依据公开发现接口展示实际启用的方法：本地密码、机器令牌及已配置 OIDC 提供方。服务端没有配置第三方登录时，不出现模拟企业登录按钮；输入的工作空间地址变化会取消旧发现与旧登录事务。

真实事务流程：

1. 客户端以安全随机数创建 verifier，仅保存在发起客户端内存；发送其 SHA-256 base64url challenge。
2. 服务器返回 `authorization_url`，通过系统浏览器打开；系统打开失败时可复制本次真实授权链接。
3. OIDC 回调页面提供短时、一次性授权码。用户将该码填回发起客户端。
4. 客户端在 exchange 请求体提交 code 与 verifier，成功后接收普通办公会话，与密码登录共用身份状态。

```text
GET  /api/im/auth/providers
POST /api/im/auth/oidc/:provider/start
POST /api/im/auth/oidc/:provider/exchange
```

code challenge 与 verifier 分离；verifier 不放进 URL，办公长期令牌不进入第三方授权 URL。身份映射可以指向 human 或 agent，类型本身没有额外权限。缺少映射、提供方停用、授权失败与限流分别显示业务错误。

已验证的是客户端真实协议与受控提供方交互，不宣称完成某个外部企业账号的生产登录验收。生产身份提供方配置、账号映射和签名交付另见相关服务端与生产记录。

直接依赖增加 `crypto` 与 `url_launcher`，对应原生注册代码由 Flutter 生成。依赖已通过官方包源正常解析；本批检查使用 `--no-pub`，没有重新下载或更换来源。

主要实现：`auth_providers.dart`、`login.dart`、`office_state.dart`、`main.dart`。

## 4. 每个会话中的 Agent 主动性与真实回执

会话 Agent 协作入口可以打开“主动性与工具范围”。配置按 Agent、会话分别保存，控制是否主动执行、每次最多步骤数、允许动作集合和主动复核间隔；active/mentions/paused 参与模式保持独立。

```text
PATCH /api/im/rooms/:rid/participation
{
  principal_id,
  base_revision,
  autonomy: {
    enabled,
    max_steps: 1..4,
    allowed_operations: [...],
    review_interval_seconds: 60..86400
  }
}
```

只有 Agent 自己或会话 owner 可修改，服务器最终授权。缺少服务端 autonomy 数据时客户端明确只读，不把默认开关伪装成已经支持。冲突读取针对该会话执行，不切换用户当前 IM 会话；本地编辑不会被悄悄覆盖。

可选动作来自服务器 `autonomy_available_operations`：任务创建/更新、添加联系人、日程创建/更新/响应，以及在真实 canonical 文档适配器接通后提供的共同文档创建/更新。客户端不会把尚未接通的文档能力固定显示为可用。

工作记录展开行动计划，并读取 `GET /rooms/:rid/turns/:tid/plan` 的执行回执；“刷新行动与回执”读取服务器结果及已持久化的恢复状态，不触发第二次执行。

| 回执 / 运行情况 | 客户端状态 |
| --- | --- |
| `committed` | 已提交，并可查看资源、版本与提交时间 |
| `rejected` | 已拒绝，保留拒绝依据 |
| `applying` | 提交待确认，不显示成功 |
| 活跃运行中的无回执步骤 | 待执行 |
| 取消、过期、失败或完成运行中的无回执步骤 | 未执行 |

运行取消不会让已经提交的业务回执消失。计划文字、模型说“完成”和整个运行 completed 都不能代替 committed 证据。普通界面使用办公动作名称；机器字段、operation_id、版本、原文依据等保留在可展开详情内，方便人和 Agent 核查。

主动调度、预算、租约、幂等与 canonical 文档恢复的服务端实现详见 [原生动作实现记录](NATIVE_ACTIONS_IMPLEMENTED_1520.md)。

主要实现：`agent_autonomy.dart`、`agent_action_plan.dart`、`agent_collaboration.dart`、`office_state.dart`、`office_dialogs.dart`。

## 5. 手机消息编辑与办公工具

手机会话输入区域提供展开编辑器，长消息可在完整页面编写，点击“完成”把内容带回原会话草稿再发送。点击关闭放弃此次扩展编辑，保留原草稿。控制器由编辑器自身 State 管理，避免关闭动画期间被提前释放。

## 6. 跨办公内容的结构化搜索

搜索分类直接发送到服务端，覆盖消息、文档、任务、联系人、Agent 好友、Agent 商店、邮件、审批和日程。作者/发起人、所属会话、日期范围也传到后端，筛选不局限于已返回的 200 条本地结果。

```text
GET /api/im/search
q=<keyword>
type=message|task|document|person|agent|store|mail|approval|calendar
room_id=<optional>
author_id=<optional>
after=<inclusive ISO timestamp with timezone>
before=<exclusive ISO timestamp with timezone>
```

客户端把所选开始日本机午夜转换为 UTC `after`，把结束日下一日本机午夜转换为 UTC `before`，因此包含整个结束日。文档按 canonical 更新时间与可确认的当前内容编辑者筛选；其他内容按发送或创建时间。没有可信当前作者的文档不会假冒历史作者。

选择联系人或 Agent 目录分类时清除无意义的作者、会话及日期过滤；选择邮件清除会话过滤。全部分类下启用作者/日期后，不含缺少相应字段的目录条目；指定会话后，只搜索实际关联内容。筛选对话框写明这些语义。

服务器 `truncated` 为真时显示“当前只展示部分匹配项”，建议增加条件；请求失败显示独立错误状态，避免把之前分类的结果当成本次成功返回。意图序号处理相同关键词、不同筛选的并发状态更新。

桌面支持 `Cmd/Ctrl+K` 打开搜索、`↑/↓` 选择并滚动结果、`Enter` 打开、`Esc` 返回。输入法仍有 composing 内容时不执行打开。结果导向既有业务页面，文档和任务沿用显式 roomId 的独立业务打开方式。

主要实现：`search_filters.dart`、`office_shell.dart`、`office_state.dart`。

## 11. 手机 Agent 消息中的执行附录

补充时间：2026-09-06T15:56:45+08:00。iPhone 实际登录演示群后发现，服务器追加的动作回执原文含 operation 名称与长资源 ID，会占据大量消息屏幕。本批在保留业务正文的前提下，将可验证绑定的附录收进“执行原文”折叠项，并提供“查看工作记录”直接进入现有真实回执弹窗。

折叠同时要求 Agent 作者、消息 `turn_id` 与当前会话的实际 run / principal 匹配，消息全文与 `turn.result.content` 完全一致，并且末尾附录与 `turn.result.action_summary` 按服务器格式逐字相同。不是通过发现任意一段 `[服务端动作回执]` 文字就隐藏内容，也不会把正文中模型自己写的同名标记删掉。

“已提交 N 个动作”的数量另外核对各条 `action_receipts`：operation_id 唯一，turn、principal、operation、status、resource、revision、error 字段均吻合。`applying` 只显示“提交待确认”；缺失或不匹配的回执只显示“执行明细”。旧消息不在当前返回的最近20轮工作记录内、作者不匹配、普通用户手写标记或消息被编辑后无法匹配运行全文时，保留原始全文，不生成未经核验的成功状态。

该组件不额外为每条消息发起网络请求。点击工作记录才沿现有 `getRun → /turns/:id + /plan` 读取真实执行证据。复制消息、附件、回复和正文不变；执行原文仍可展开、选择和核查。
