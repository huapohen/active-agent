## 已接通的办公入口

桌面“消息”标题右侧三条杠展开应用导航与会话列表之间的160px分组列，再次点击可收起。手机消息筛选行左侧三条杠打开约78%屏宽的左侧抽屉。分组选择过滤当前消息列表，不切换用户身份，也不修改会话成员。

侧栏顶部齿轮打开真实“编辑分组”。手机采用全屏编辑页，桌面采用居中编辑窗口。页面分为常用分组、侧栏分组、标签顺序、隐藏四区；消息固定第一且不能隐藏。常用分组上限8项，消息固定，其他可移除或通过加号添加；侧栏显示与常用分组分别保存，隐藏的侧栏项仍可保留在常用入口中。

分组排序支持拖动及上移/下移。内置分组与标签分别在各自区域内排序；前端不提供两类条目跨区拖动。侧栏中的“标签”是可折叠容器，不是后端额外的筛选ID；其中标签按服务端order的相对顺序展示。不能将该实现描述为支持任意内置/标签交错排序。

消息列表的标签标题有“…”菜单，连接“添加会话”“编辑标签与规则”“删除标签”。会话行“…”、长按和桌面右键都能打开“整理会话”，修改本人标签、标记、已完成。它们不是修改工作群的名称、成员或任务状态的操作。

## 实际支持的内置分组

| 语义ID | 当前依据 |
| --- | --- |
| messages | 当前身份可见的全部会话 |
| unread | 真实未读数大于0的会话 |
| marked | 本人单独标记的会话，与顶部收藏独立 |
| mentions | 包含未撤回且提及本人的消息 |
| direct | 人类或Agent参与的双人会话 |
| groups | 群会话，包含人机混合群 |
| muted | 本人开启免打扰的会话 |
| agents | 对方是Agent的双人会话 |
| completed | 本人标为已完成的会话，不改变群聊或任务状态 |

所有筛选使用服务端返回的room_ids，再与当前OfficeState中的会话取交集。普通消息分组也使用这个可见集合。人类单聊、Agent单聊和混合群使用相同的标签写入协议与成员权限。

参考软件中的云文档、话题、机器人、服务台、高级消息展示规则等没有在本批后端中提供相同数据语义，因此没有添加空入口或用现有任务状态冒充结果。

## 标签与会话归组

新建标签包含名称和可选的“会话名称包含”规则。规则为空表示没有自动匹配。服务端按实际可见会话名称匹配；规则与手工加入的会话取并集。用户可以编辑名称、增加/清空规则、批量添加会话、删除标签。

“添加会话”在宽屏使用候选会话与已选会话双栏，手机使用单列和真实选择数量；搜索按当前可见会话名称筛选。已经在标签中的会话显示为灰色勾选。批量提交一次add_room_ids，由服务器先验证全部会话权限再整体写入；不会逐个循环写出半批结果。

“整理会话”重新读取真实会话归组，再显示manual_group_ids和matched_group_ids。自动规则命中的标签保持勾选并禁用直接移出，说明需要编辑规则；其他手工标签可以增删。标记与已完成是独立个人偏好。删除标签只删除个人标签及关联，会话和消息保留。

## 持久化与冲突协议

```text
GET    /api/im/message-groups
PATCH  /api/im/message-groups
POST   /api/im/message-groups
PATCH  /api/im/message-groups/:label_id
DELETE /api/im/message-groups/:label_id
GET    /api/im/rooms/:room_id
PATCH  /api/im/rooms/:room_id/message-groups
```

完整快照含revision、updated_at、order、hidden_ids、shortcut_ids和groups；分组含真实room_ids、room_count、unread_count、type、visible等。所有修改携带个人统一base_revision，不改变room ACL。名称匹配规则使用name_contains；会话详情的字段为room.message_grouping。

编辑器在initState立即捕获身份、基线版本和草稿，不能等到保存时才惰性读取版本。后台刷新不会偷偷替换正在编辑的基线。遇到409保留排序、输入或选择，并提供显式读取最新数据的入口，再由用户重新保存。布局合并会删除已不存在的ID、保留仍存在的本地排序并追加服务器新建分组；不静默覆盖整个远端布局。

新建标签使用一个在弹窗生命周期内稳定的client_id。网络结果不确定后重试沿用原意图，不因每次点击生成新ID而制造重复标签。

## 身份隔离与热重载

controller以工作空间地址、实际principal ID和连接状态绑定数据。身份变化立即清空snapshot、选中项和错误状态，再接受新身份的版本；新身份revision较小也能正常加载。每次异步请求捕获身份generation，旧身份慢响应不能覆盖新身份数据。

已打开的真实编辑窗口在身份变化后整体替换为“当前身份已变化”，隐藏旧标签和草稿。各写入入口仍单独校验最初身份，防止同revision下使用新身份凭据提交旧身份草稿。数据加载失败时显示重试，不能把失败响应显示成已保存。

OfficeShell通过nullable惰性getter创建controller，首帧结束后读取分组，dispose仅回收已创建的实例。新增功能可以热重载进入已运行的Mac/iPhone窗口，无需通过hot restart清掉用户登录。

## 相邻小修

真实默认好友按system_agent_key排序：activate-agent第一、desktop-companion第二，其余保持原有顺序。只重排服务端已返回的身份，不插入默认假名片，也不将某一位Agent标成唯一主动者。所有Agent好友、会话成员与Agent协作面板均可进入人格配置；写权限仍为该Agent本人或会话owner。

当前人格配置实际提供的是按会话的active/mentions/paused与独立autonomy策略。尚无跨会话的默认人格字段或自由编辑人格指令界面，不能把当前入口称为完整的全局人格编辑器。

妙记录音选择器与API共用后端支持的8种格式：MP3、M4A、WAV、OGG、AAC、OPUS、FLAC、WEBM。移除不能绑定妙记录音的MP4，补齐OPUS/FLAC；未知后缀在上传前报错。附件层会把非图片MIME规范化为application/octet-stream，妙记绑定依据允许的音频后缀，不以客户端声明的video/mp4绕过检查。该修复没有宣称进行音频编解码或自动转写。
