## 接入 IM 的最小缺口

这个独立服务的 bearer 是实例级控制权，目前没有 IM principal/room、稳定操作 ID 或持久化任务归属。最小适配器应在 Doc Free 成员权限后建立 `principal_id + room_id + companion_session_id` 绑定，把服务凭据留在本机后端，每次提交/轮询/截图重新检查当前会话和应用权限；保存稳定操作意图、任务 ID、真实结果和截图引用为人/Agent 可见记录，再异步执行以免占住 IM 串行事务。现 API 不能保证跨断线或重启的提交幂等，需增加 client_id 去重与可查询回执或在未知结果时要求核对，不能盲目重发点击。取消目前是关闭整个会话且删除服务内回执，适配器要先保存已有结果并明确可能已经发生的页面副作用；权限撤销应立即关闭绑定上下文。运行时可用性应根据实际服务和会话创建确认，不能由商店模板或 `health.ok` 推断设备已经授权。

这仍是浏览器 HTTP 中转与受限操作服务，不是系统网络防火墙或任意恶意网页沙箱。共享 worker/未覆盖传输、浏览器漏洞、原生跨 App、iOS、硬件、单个任务取消和长期任务持久化均未在本审查中扩建或宣称完成。
