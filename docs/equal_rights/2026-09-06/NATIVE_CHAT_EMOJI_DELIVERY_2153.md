## 桌面侧栏、手机更多与工作台返回

桌面侧栏已经接入右键、长按、Shift+F10 和菜单键，进入同一个锚定快捷菜单。菜单提供打开、上移、下移、从导航栏移除和编辑导航栏。编辑器支持增加、移除、排序和恢复默认，明确保存后才写入；至少保留一项，最多十二项。固定“设置”不能移动或移除，“更多 · 编辑导航栏”保留恢复入口。

默认顺序是消息、Agent、通讯录、云文档、任务、工作台、视频会议、日历、邮箱、考勤、审批、人机妙记。个人可以把消息或 Agent 移位、移除，不强制它们占第一栏；企业管理仍按真实权限单独显示，导航偏好不能授予企业权限或绕过应用禁用。

手机“更多”使用底部弹出面板，保留底栏可点击；再次点击“更多”关闭同一面板。遮罩、关闭按钮、Escape、系统返回或切换底栏功能均可关闭。弹层背后的页面保持挂载，因此搜索与滚动位置得以保留；被覆盖的会话停止可见阅读上报。没有把“更多”变成只能另按返回的独立整页。

工作台应用使用统一返回容器。左侧返回上一层应用，右侧关闭回到工作台；系统返回也逐层回退。工作台搜索和滚动位置保留，重复进入已在栈中的路由复用原页面，避免重复实例和 GlobalKey。未知、禁用及无权限应用同样可返回、可关闭。工作台上方打开“更多”时，第一次系统返回只关闭更多，第二次才返回上一层应用。

这些交互在同一 Flutter 源码中支持桌面与手机布局。各工作台应用内部业务能力仍按实际接入程度提供，统一返回容器不等于会议、邮箱、审批等全部业务已达到飞书的完整深度。

## Agent 好友分类树

Agent 好友提供三个可组合的维度：公司/组织及其好友实际任职部门、职业及实际职位、工作分类。它们与名称、技能、职业、组织搜索共同筛选。桌面左侧显示分类树，手机通过筛选底部面板提供同样的层级与条件；节点带数量，已选条件可逐项移除，也可重置。

## 首条未读、未读数与真实已读

会话未读数移到头像右上角，视觉上只显示一次。普通会话为红色，静音或折叠为灰色；超过 99 显示 `99+`，无障碍语义保留实际数量。单聊末条本人消息只有在服务端具备明确接收人已读证据时才显示红色单勾，收到的消息、群聊、撤回消息和未知历史不会被推断为“对方已读”。

进入有未读的会话使用 `first_unread=true` 窗口，从真正第一条未读开始；该位置不受详情最近 200 条上限影响。时间线显示“以下为未读消息”及进入时未读数，提供继续阅读后续消息、向下未读提示和跳到最新。读取更早消息时保留原可视位置；后台新消息更新既有窗口，不突然用最新尾页替换正在爬楼的历史。

界面根据实际渲染矩形与消息视口的相交情况报告可见序号。选择会话、下载一页、后台刷新、打开话题、打开阅读名单和直接请求 GET 都不自动确认整页已读。会话被更多、工作台其它页或页面面板遮住，或应用不在前台时，停止可见上报；过期身份、选择版本与未加载序号不能推进当前水位。

阅读确认沿用 `PATCH /api/im/rooms/:rid/preferences {read_seq: N}` 与 MCP `im_preferences`。水位只增不减，表达阅读到当前可见上界的累计位置；它不是逐条独立点击日志，也不能通过降低水位来实现“标为未读”。同一待确认水位去重，失败可重试，迟到响应不覆盖另一身份或另一会话。

### 收件人快照和阅读名单

新消息发送时记录真实收件人及成员加入周期，排除作者；普通消息、转发和 Agent 回合消息走相同记录路径。只有显式个人阅读确认保存 `read_acknowledgements`。加入时初始化水位、Agent worker 处理游标和执行完成均不等于已读。

`receipt_summary` 使用 `known`、`basis`、`eligible_count`、`read_count`、`unread_count`、`unknown_count`。群聊显示接收人数和实际已读数量，单聊显示明确的已读/未读状态。阅读详情通过 `/messages/:mid/readers` 与 MCP `im_message_readers` 获取，列出发送时的人类与 Agent 接收人，并标记已退出、重新加入等成员变化。

离开再加入不会用新周期的确认追认旧消息；旧周期真实确认继续保留。旧消息没有收件人证据时显示“阅读状态未知”，不拿当前成员数编造历史已读比例。已撤回消息不展示原阅读内容。名单中的“最近确认”是累计 ACK 的最近时间，不声称为该消息首次阅读的精确时刻。

## 消息右键、更多、悬浮时间与话题

桌面右键、Shift+F10、菜单键、悬浮栏三个点和手机消息长按进入共同消息动作。当前有真实动作的项目包括表情回应、回复、复制、选择文本、转发、创建话题、Agent 协作、置顶/取消置顶、阅读状态和查看原文；本人未撤回消息另有编辑、撤回。撤回消息不会残留可提交回应的快捷表情行。

手机长按由外层消息区域接收，避免被正文 `SelectableText` 抢走手势；需要精确选择文字时进入独立“选择文本”。手机动作以带时间的底部面板展示，并包含快捷经典表情与完整表情入口。桌面更多菜单使用按钮实际位置作为锚点。

桌面悬浮栏通过 OverlayPortal 叠加，不向消息行插入高度。鼠标从消息移动到工具栏和表情面板时保持打开；离开后延迟关闭。栏内提供完整表情、回复、转发、话题、Agent 协作及更多，并显示精确到秒的本地时间，遵守当前 12/24 小时制设置。真实指针测试证明悬浮前后当前消息及下一条消息的矩形完全一致，不再出现插入三个点导致的消息排版伸缩。

Agent 超级入口沿用真实同事选择、协作与消息来源，不创建假 Agent 回复。菜单、话题、协作回调绑定打开时身份及源会话；切换身份后的旧动作与迟到结果不会落到新会话。

“创建话题”打开真实 `reply_to` 回复树，手机使用可关闭底部面板，桌面使用右侧面板。GET `/messages/:mid/thread` 与 MCP `im_thread` 返回根消息和递归后代，按序号分页；Agent 执行的 `root_id` 不替代聊天回复关系。打开话题不发占位消息，不 ACK。回复通过真实发送接口明确指定源会话及被回复消息，失败保留草稿；撤回原文不可从旧版本复活。

## 完整共享表情目录

本批固定目录包含飞书公开官方参考中的 **182** 个经典图片表情，以及 Unicode **17.0** 的 **3944** 个 fully-qualified 序列，共 **4126** 个唯一 ID、十个分类。经典表情保留官方代码、名称、图像来源和逐图 SHA-256，本地打包 PNG；不再以六个快捷回应充当整个表情目录。

公开飞书参考来源为 `https://open.feishu.cn/document/server-docs/im-v1/message-reaction/emojis-introduce`，页面标示更新日期 2025-02-19。Unicode 来源为 `https://www.unicode.org/Public/emoji/latest/emoji-test.txt`，本次读取的版本固定为 17.0，源文件 SHA-256 为 `1d8a944f88d7952f7ef7c5167fef3c67995bcae24543949710231b03a201acda`。图片出处及校验清单位于 `apps/office/assets/emoji/feishu-sources.json`，第三方说明和中文名称依赖许可证随资源保存。

共享选择器同时接入输入框、消息回应、更多动作和桌面悬浮表情。提供经典表情、全部、最近使用、其它类别、中英文名称/代码/Unicode 搜索、惰性网格、鼠标大图预览和手机底部面板。预览不会选择或改最近列表，屏幕变窄时仍遵守容器约束。

经典回应的规范 ID 为 `feishu:SMILE`；消息正文使用稳定 token `:feishu:SMILE:`。Unicode 保持完整原序列，包括肤色、性别和 ZWJ。正文和话题内已知 token 渲染为图片，未知 token 保留可见原文；复制、导出和协议保存原始文本，不能从消息 token 构造任意本地路径或远端资源 URL。

这一数量证明公开参考目录与 Unicode 17.0 的覆盖，不包含未公开的企业自定义表情包、个人收藏贴纸，也不据此宣称最新飞书客户端全部扩展素材或所有平台系统字形已逐项验收。
