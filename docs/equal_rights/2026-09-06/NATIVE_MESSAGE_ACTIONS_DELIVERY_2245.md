## 关键消息操作闭环

手机菜单从全量网格改为真正的可拖动分组面板：首行保留高频四格，后面按语义分组，展开与内层滚动共用 ScrollController。桌面在可选择正文里右击时，原文本工具栏先退出，再在下一帧打开消息菜单，防止 build 阶段导航、重复菜单或只有复制/选择文本的半套入口。

多选绑定当前身份代次、会话和真实消息 ID。执行前重新读取每条来源；已隐藏的消息不会继续复制链接或转发。逐条动作中途失败，已经成功的条目不参加下一次重试，界面保留未完成集合。取消多选恢复原输入区域，菜单覆盖期间底层时间线不产生新阅读确认。

新链接与个人集合接入现有时间线定位。定位先读取目标，再按目标序号取得窗口；目标在这两次读取之间消失时显式失败，不用下一条消息冒充目标。旧身份、旧请求和后来的导航之间按版本判定，防止迟到响应把用户拉回旧会话。

## 本人标记、隐藏与作者转发限制

`PATCH /api/im/rooms/:rid/messages/:mid/preferences` 只接受本人 `marked` / `hidden` 布尔值，不接受 owner 或 principal 覆盖。重复显式 false/true 不反复写事件。个人隐藏会从本人窗口、首未读、预览、搜索、线程、置顶清单和新的 Agent 上下文中移除消息；其他成员原文保持可见。本人被隐藏消息作为直接 ID 或隐藏线程根读取时，只返回安全墓碑。

`GET /message-marks` 与 `/hidden-messages` 支持 `room_id`、limit、before。界面按 50 条分页，标记清单可打开原消息、取消标记；已删除清单只显示作者与时间并提供恢复。恢复成功后实际重新 GET，列表刷新失败会独立说明，不用本地删行伪造成功。界面自己也剥离隐藏响应中意外出现的正文、历史或附件，撤回正文不可恢复。

消息标记与旧 `message_grouping.marked` 手动会话开关兼容；`marked_message_count` 与 `conversation_marked` 说明会话进入标记分组的不同来源。会话 favorite 不是消息标记的替代品。

作者通过 `/messages/:mid/forwarding` 及 `base_revision` 修改自己的开关。`no_forward` 是包含来源链的有效保护，`forwarding_own_no_forward` 才是作者本条自己的开关。转发副本不能靠清除自身标志绕过原消息保护；受保护附件 ID 不能直接重用来绕过原生发送限制。

## 原子来源任务和文档

创建命令为 `/rooms/:rid/messages/create-task` 与 `/rooms/:rid/messages/export-document`，共同需要稳定 `client_id`、1–50 个唯一 `message_ids`、精确对应的 `base_revisions` 和标题。任务可带 description、assignee_id，文档可带 content；这些正文参数仅为人或 Agent 的补充说明。

服务端在同一 IM 串行操作中核对成员、目标 tasks/docs 应用策略、消息可见/未撤回/有效禁转/版本，然后生成真实源正文、当前作者、发送时间、消息 ID、版本与附件索引。面板的 GET 前检用于可读错误和最新预览，真正安全边界是服务端原子命令，避免来源在 GET 与普通创建 POST 之间改变。

源文本以足够长的代码围栏保存，经典表情 token 和复杂 Unicode 原样保留；用户补充独立列出，不重复粘贴两次来源。返回真实 task/document、源 IDs、源版本和 duplicate。目标正文超过限制明确拒绝，不静默裁掉来源。不会为创建任务或文档再向群里发一条占位消息。

前端等待中保留同一 payload / client_id；网络或 503 未知结果冻结编辑，重开同身份同来源面板仍保留待确认意图。查询 `/messages/source-operations`：pending 只显示待核对，不重复创建；completed 根据 resource_id 读取真正资源。服务器先持久化文档来源意图，再跨规范文档存储创建，响应丢失的 pending 不擅自当作失败重发。身份变化、关闭面板或迟到响应不会把旧成功提示放到新身份。

同一个 client_id 的不同请求返回 idempotency_conflict；面板保留原意图，不能另造 ID 绕过。来源版本 409 保留草稿，要求读取新来源后再次明确提交。未知规范文档结果仍需要核实恢复，本批提供安全待确认状态，不声称这类异常已经自动恢复完毕。
