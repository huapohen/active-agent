## 可操作流程

手机继续使用已校准的固定 mic 槽位，启用后不向工具栏增加动态发送按钮。桌面从既有“更多工作工具”菜单打开“语音消息”，不改变桌面工具行已有图标位置。

打开独立面板先读取 `/capabilities`，服务未启用、缺少有效时长限制或请求失败时显示可重试反馈，不申请麦克风。只有点击“开始录音”才调用 `startFromUserGesture()`。面板具备开始、停止、取消、重新录制、试听、暂停、进度定位和发送；关闭面板或独立语音发送均不修改原输入框文字、富文本、提及与附件草稿。

录音中的音量条来自媒体驱动实际 dBFS 事件，无事件时显示“等待麦克风音量”。没有用随机动画模拟波形。录音结束时显示真实 WAV 解析时长；达到媒体服务的时长上限只保留服务裁出的实际 PCM 帧，并告知保留时长，不自动发送。语音气泡使用标准音频图标和真实播放进度，没有声称图标是原录音波形。

播放完成后可以重播；资源已释放的完成状态不会启用无效的进度拖动。音频附件继续提供原有鉴权下载功能，增加播放器没有移除文件保存能力。

## 协议与身份边界

`OfficeState` 新增可注入 recorder/playback factory，默认使用 `voice_audio.dart` 的真实平台服务。UI 不直接管理插件通道，测试替换驱动与存储，无需申请系统麦克风。

| 操作 | 请求与职责 |
| --- | --- |
| 能力读取 | `GET /api/im/capabilities` 的 `voice_media`；读取 enabled、max_duration_ms、max_attachment_bytes |
| 上传录音 | `POST /rooms/:sourceRoom/attachments`，固定原会话、client_id、filename、mime_type=audio/wav、data_base64 |
| 发送语音 | `POST /rooms/:sourceRoom/messages`，固定 client_id、空 content 与 `voice:{attachment_id}` |
| 下载/播放 | `GET /rooms/:room/attachments/:id/content` 使用当前 Bearer header；不把 token 放进 URL，不改为公开文件 |
| 清理未发送录音 | 只在同一身份代次下删除明确返回的原会话附件；未拿到 ID 的不明上传无法假装已清理 |

发送时不自报 `kind`、duration、sample_rate 或其他语音元数据。服务器根据实际 RIFF/WAVE 字节验证 PCM16、单声道、实际采样率 8–48 kHz，并生成消息 `kind:'voice'` 与 `voice`、附件 `audio` 元数据。客户端优先请求16kHz，但不能把请求参数冒充硬件实际采样率；UI接受服务端数值型小数 duration_ms。

人类与 Agent 的发送请求结构一致，服务端从登录身份判断作者。Agent 可通过同一协议提交合法音频附件；协议请求不会绕过本机 UI 的麦克风手势与权限流程。本轮不包含语音转写、ASR、语音生成或 Agent 自动监听。

## 草稿、失败和迟到回调

每个录音面板捕获端点、principal ID、身份 generation、来源会话和 conversation selection。换账号、换端点、离开后重开原会话（A→B→A）都使旧面板失效。权限、停止录音、上传和下载的迟到回调重新校验上下文，不能复活旧录音或把它发送到新会话。

上传与消息发送分别使用稳定的 client_id。上传失败保留同一 WAV 字节和上传编号；消息发送结果未知时保留上传附件与同一个消息编号，重试不产生新的发送意图。界面会说明“重试会沿用同一条语音的发送编号”。一旦消息请求已经提交，按钮只称“关闭”，不误导用户以为可以撤销在途消息。

未提交消息的已知附件可以在关闭或来源变动时清理；如果发送已提交但结果未知，客户端不自动删除附件，因为它可能已经属于服务端成功发送的消息。异步清理也不能借新身份删除旧身份的对象。

应用进入 hidden/paused/detached 会取消录音、停止试听并使旧操作失效；resumed 不自动恢复录音。系统权限弹窗造成的短暂 inactive 不等同于后台，避免自己取消正在等待授权的流程。若在消息发送中退到后台，面板提示回到原会话核对结果，不声称撤回已提交发送。

## 播放与消息生命周期

`OfficeState` 对消息音频共用一个播放会话，下载时即绑定原身份/会话/选择代次。点击第二条会停止第一条；实际媒体服务进一步协调预览、录音和会议焦点，避免混播。身份变化、离群导致当前会话失效、页面隐藏、语音附件失效/撤回而卸载气泡时都停止旧播放。

播放/暂停/进度/真实时长与错误重试由服务状态驱动。进度条预留固定高度，点击播放不插入额外行撑开消息排版。下载失败保留明确的重试入口。

widget 回归发现一个实际生命周期问题：移除正在播放的气泡时，播放器同步通知会撞上 Flutter 锁定的 widget 树。修复为立即递增操作版本、使旧下载失效，随后在微任务中停止播放器并通知；停止前再次核对版本，旧清理不会覆盖新播放。`OfficeState.dispose` 使用媒体服务的 dispose 路径抑制销毁中的通知。
