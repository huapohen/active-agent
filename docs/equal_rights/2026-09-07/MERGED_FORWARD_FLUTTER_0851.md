## 已实现交互

- `showOfficeMergedForward`：桌面居中对话框；窄屏为可避让输入法的底部面板。来源预览、最近会话搜索、单选／多选切换、最多 20 个目标会话、附言、选择明确提及的人类或 Agent、取消、发送。
- 发送前刷新 1–50 条来源消息及版本，并验证所有目标会话当前成员。多目标附言仅允许提及所有目标的共同成员；使用稳定成员 ID，不把 `@名字` 文字误当作原生提及。
- 来源变化时更新预览并要求重新核对，隐藏、撤回、禁止转发、权限失败会阻止旧预览提交。服务器仍执行最终原子权限及版本检查。
- 有效回执自动关闭并返回结果，让集成方只在确认投递后清除多选。取消返回空结果。修复成功后点遮罩可能丢失返回值、保留已发送选择的问题。
- `OfficeForwardBundleCard` 展示真实 `forward_bundle` 描述和预览；点击读取接收会话中的共享记录，支持三层内嵌套记录、来源作者／时间、原文及目标附件保存入口。卡片附言和原文为不同内容。
- `officeForwardBundleCopyText` 先验证当前卡片，再读取共享记录，递归复制作者、时间、正文、嵌套内容和附件文件名。目标成员无需进入来源群，接口失败不输出卡片摘要充当原文。

## HTTP 合同

| 操作 | 接口 | 客户端行为 |
| --- | --- | --- |
| 合并投递 | `POST /rooms/:rid/messages/forward-bundle` | 单个原子意图包含 `client_id`、精确来源版本、目标会话及附言提及 |
| 原回执确认 | `GET /rooms/:rid/messages/forward-bundle-receipts?client_id=…` | 发送结果未知时先查询同一意图；已有回执直接恢复成功 |
| 共享记录展开 | `GET /rooms/:rid/messages/:mid/forward-bundle` | 校验 room、message、bundle ID 及 `shared_copy` 策略 |
| 复制前卡片检查 | `GET /rooms/:rid/messages/:mid` | 拒绝隐藏／撤回／错误会话／错误 bundle 引用 |
| 附件内容 | 当前目标会话的附件内容接口 | 使用现有成员鉴权下载；不使用服务端返回的任意跨端点 URL |

投递结果未知时锁定来源、目标、附言和提及。没有回执时只重试原 `client_id` 和原 payload；取消后同一客户端身份重新打开仍能恢复。来源后来编辑／撤回，不影响先查询原回执。收到结构不完整的回执不能报告成功，也不能自动新建意图。

每一个异步阶段均绑定身份代次、端点、成员和来源会话；来源分批请求之间和目标逐个读取之间重新验证。换账号后停止后续请求并清空显示内容，旧请求响应不能写入新身份界面。共享记录完整校验后才显示，错误条目不能被列表转换静默丢弃；附件必须属于当前接收会话，最多三层、展开 200 项。
