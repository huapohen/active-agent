## 桌面与手机的真实功能

- 桌面输入框保留紧凑高度，多行输入自然增长；提示为“发送给 当前会话名称”。文字排版、emoji、@、原生截图及选项、Agent 协作、更多工具、展开、发送和发送方式均有对应真实入口。
- 更多菜单保留附件、共同文档、任务、日程、会议、工作记录能力；日程与会议依赖 shell 传入真实路由回调，由本轮主任务补齐桌面传入。没有把菜单项目做成静态展示。
- 发送图标在空白、离线、上传未完成或发送中时不产生新提交；手机空输入不显示发送按钮。桌面不再使用占空间的蓝色文字发送按钮与永久快捷键提示。
- 发送快捷键通过现有鉴权设置接口及 `base_revision` 比较更新，不只修改界面开关；输入法组词期间 Enter 不误提交消息。
- 手机输入框与灰色工具行分离，工具顺序为 emoji、@、麦克风、图片、Aa、+，另保留 Agent 入口。Aa 切换为真实格式工具行，+ 再次点击关闭；展开编辑器保留输入法避让空间。
- 麦克风尚未接入真正录音服务，因此明确禁用并说明状态；不会点击后假装已录音或提交。

## 富文本和展开编辑器

主输入使用 `OfficeRichTextEditingController`，真实显示加粗、斜体、下划线、删除线；插入、删除和替换文字会同步调整 UTF-16 样式区间。提交时正文与样式一起裁切首尾空白；纯文本继续走既有 Agent 内容渲染与附录逻辑。合并记录正文也能显示同一原生样式元数据。

展开编辑器支持标题、正文、emoji、成员提及、图片、格式、缩进和 Agent 提及。结果返回当前草稿，再由会话既有发送通路统一提交；展开面板本身不直接写消息。标题存入当前身份／会话草稿，发送时成为真实第一行及加粗区间，反复展开不会重复叠加标题。正文第一行被用户手动改写后不会擅自移除不匹配文本。

附件选择、截图返回、展开回写都重新检查身份代次、端点和会话；切换身份或会话后，迟到结果不能写入新草稿。跨版本开发热加载时，控制器类型从普通控制器升级为富文本控制器需要完整 Flutter restart（`R`）；此前一次 `r` 保留旧类型后出现 cast 错误，不能把它记作成功热重载。主任务负责原生重启及重新登录。

## macOS 原生截图接入

桌面截图通过 `OfficeScreenshotService` 调用真实 `renji/native_screenshot` 通道。依次检查能力、必要时显式请求屏幕权限、选择区域、返回 PNG、作为待发送附件进入既有上传流程。截图取消不上传、不自动发消息；“截图时隐藏人机窗口”将明确选项传入原生服务。未接入的平台如实显示不可用。原生 Swift 能力实现与构建由对应专项记录说明，本组件测试不替代 macOS 权限弹窗和实际截图验收。

## 原生合并转发与编辑补全

本轮会话集成保留真实多选合并转发、回执验证、接收会话共享快照读取和未知结果恢复。复制单条合并卡片、多选复制、选择文本中的“复制全文”都会校验当前卡片，再读取真实共享记录正文、作者、时间、嵌套内容及附件文件名；不把附言或摘要冒充原文，也不要求进入来源群。

原生合并卡片的附言允许清空，卡片与共享原文保留；桌面右键与手机长按进入“编辑消息”后保存空附言均有真实界面回归。普通无附件文本仍不允许保存空内容。编辑／排版期间来源撤回、身份更换和迟到弹窗回调保护由共享富文本与编辑面板实现。
