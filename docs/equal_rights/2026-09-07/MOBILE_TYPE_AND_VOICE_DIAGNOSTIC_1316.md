## Mac 原生语音启动失败的定位

真实 Mac 首次点击“开始录音”立即失败，原先的笼统提示无法区分权限、格式、临时目录或原生录制接口。现在 `OfficeVoiceRecorder` 为启动各阶段生成稳定诊断：`focus`、`permission`、`encoder`、`storage`、`start`、`amplitude`、`state`。

日志和用户错误码采用 `VR-阶段-异常类别`。只输出固定枚举值，原生平台错误码仅允许固定的 `record`；不输出原始异常正文、文件路径、平台 details 或堆栈。若清理也失败，另外保留 `VR-cleanup-*`，不让它覆盖真正的启动失败阶段。设备未能关闭时保留音频占用，不允许同一录音器立即启动第二个设备会话。

已通过源码检查确认 `path_provider_foundation 2.6.0` 使用 Dart FFI，生成的 Dart plugin registrant 已注册它；Swift registrant 中没有该插件是其正常实现方式。

主任务在真实 Mac 热加载后已取得 `VR-storage-filesystem`。对应原因是 `getTemporaryDirectory` 返回的应用缓存目录尚不存在，而录音存储直接调用 `parent.createTemp`。`path_provider_foundation` 的临时路径查询不会主动创建该目录。存储层的父目录创建和失败后可重试修复由并行后端任务接管，最终原生录制成功与否由主任务重试记录。
