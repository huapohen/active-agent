## 人机本批实现范围

桌面成员详情由居中对话框调整为右侧抽屉，宽度为 480 个 Flutter 逻辑像素，贴右边界，内部正文可滚动。手机窄屏继续使用可关闭的全屏详情。网页截图的像素和 Flutter 的逻辑像素并非天然一一对应，本轮布局断言不证明逐像素等价。

详情新增上一个、下一个，范围是打开详情时捕获的当前筛选页成员顺序。首尾禁用对应方向；加载期间禁用重复切换和编辑；切换先清除上一成员的详情，再读取所选成员。界面明确标注「当前筛选页」，没有把当前页导航描述成跨全部成员的翻页。

人机本批包含「基本信息」「工作信息」两个页签。基本信息承载管理角色、账号状态与成员编号；工作信息承载部门、任职组织、职业、职位、来源组织和加入时间等已有字段。保留现有「编辑成员资料」入口，继续使用服务端授权的管理能力。

本批没有实现飞书参考中的自定义、其他两页，也没有新增「更多操作」菜单中的变更部门、离职、暂停账号、资源转移工作流。已有成员编辑能力和这四个独立动作不是同一份验收结论。

## 人与 Agent 使用同一权限和详情接口

详情读取仍经 `EnterpriseState.readMember` 调用 `GET /enterprise/admin/members/:id`。服务端返回的角色与 capability 决定访问和编辑能力，不按 Human 或 Agent 类型放宽权限。前后切换同样读取实际成员详情，包含 Human 与 Agent；这不是另建一套只供人使用的资料缓存。

`EnterpriseState` 的身份快照新增 `OfficeState.identityGeneration`，与 endpoint 和 principal ID 一起判断当前身份。即使同一个 principal ID 再次登录，旧管理页面也失效；迟到的详情响应不能把旧会话资料填回新登录状态，旧详情不再提供编辑或复制入口。

关闭动作带一次性和当前路由守卫，避免重复回调连续关闭底层页面。这里验证的是本次成员详情路径，不由此推断全应用所有弹窗都已完成同样检查。
