# Active Agent

**让人和 Agent 在同一个办公现场推进工作。**

`equal_rights` 从已完成的 `evolve` 文档协作基础继续发展，新增原生 Active-Agent-Native IM。产品定位是办公协作软件：会话组织讨论，任务承接责任，文档沉淀共同依据，Agent 以团队成员身份持续参与。

**当前入口：0.6 原生办公预览 · 人机。** 本轮包含100个职业模板与电脑/手机两种机伴、每位同事的参与方式和主动策略、8种真实办公动作、Doc Free单文档富文本协作、可配置OIDC登录和结构化全局搜索。准确实现commit、时间、构建归属与实测结果见 [0.6发布记录](docs/equal_rights/2026-09-06/RELEASE_0_6_1600.md)；历史0.5安装包与记录不冒充本次产物。

## 原生人机办公

人和 Agent 都有独立身份，可以创建会话、发送消息、成为任务负责人、编辑共享文档。权限来自会话成员资格和所有者角色；身份类型不会让任何一方天然获得管理权限。

Agent 不需要人不断刷新和转发上下文。分配给它的任务、会话消息和共享文档变化会产生可处理的工作；主动参与、仅提及、暂停三种模式决定介入范围。每位Agent按会话配置可用动作、每轮1至4步的上限和主动复核间隔；显式Agent交接另有因果深度和回复预算。

商店提供102个模板：100个职业同事与电脑/手机两种机伴，可按职业、职位、技能和来源组织筛选；机伴明确显示设备运行环境与实际操作边界。安装后成为独立同事，来源组织与当前任职组织分开展示。每位Agent均有按真实会话配置的人格入口，主动参与、暂停参与和自主动作分别控制。目录不会启动100个模型进程；本机fleet只为符合条件的已安装同事安排受限工作器，并限制模型并发。

每次调用模型前，系统保存该轮可见消息、文档版本、任务、输入指令、模型配置与遗漏说明。Agent公开计划后按自己的身份执行允许的动作，服务器保存真实资源与执行回执。正文、依据、计划、已提交或待确认结果都能在办公界面核查。内存和数据库承担保存与运行职责；共同工作上下文不能只存在于Agent的私有记忆里。

## 一条完整办公链路

1. 在项目会话中说明目标与约束，把行动项创建为任务。
2. 为任务指定人或 Agent 负责人，团队共享同一组文档。
3. Agent读取可见上下文并公开行动计划，执行权限与预算范围内的真实业务操作。
4. 成员在“工作记录”核查输入依据和资源回执；消息中已验证的执行附录折叠展示，原文仍可展开。
5. 从文档的“协作编辑器”进入Doc Free富文本共同编辑，继续讨论、修改文档和更新任务；版本冲突保留内容和本地草稿。
6. 断线后按游标恢复消息，进程重启后读取持久化计划与回执；提交结果未知的文档动作保持待确认，不盲目重做。

当前8种动作是：创建/更新任务、添加同事为联系人、创建/更新/响应日程、创建/更新共同文档。文档动作需要接通canonical文档适配器；任务完成必须引用领取时捕获的共同文档依据，模型一句“已完成”不能替代真实写入与验证。

## 本机体验

完整安装命令见[英文首页](README.md#start-locally)。两个仓库均切到 `equal_rights`，在 active-agent 中执行：

```bash
python scripts/dev_office.py --doc-free ../doc-free
```

本机目录名为 `doc_free` 时，使用 `--doc-free ../doc_free`。先按 [Flutter 五端构建说明](apps/office/README.md) 构建 Web，打开 **http://127.0.0.1:3218/office/**；轻量 HTML 预览仍在 **http://127.0.0.1:3218/im**，用已忽略的 `data/office/access.json` 中 `human.account.username` 与 `human.account.password` 登录（令牌保留在高级入口）。该文件权限为 0600，只用于本机；Agent 使用自己的凭据在后台参与。

工作区已包含一份团队工作约定。创建任务并把负责人设为 Active Agent，即可观察真实工作过程。模型配置沿用 `.env`；可以使用 `--no-worker` 单独体验会话、任务与文档功能。

原 `evolve` 文档工作台保留，仍可通过 `scripts/dev_workspace.py` 启动。原生IM的个人凭据与旧工作台管理凭据分离。当前普通人类和Agent成员可从有权访问的文档打开单文档富文本编辑器，短期编辑会话接入canonical Yjs协同并持续复核权限；原始办公令牌不进入浏览器URL，也不赋予旧工作台管理员权限。带版本检查的Markdown编辑继续可用。

## 五人团队的低资源体验方案

用一个macOS客户端、一个已有iPhone模拟器和三个独立Web会话登录五位人类，再安装三位Agent同事。所有人共享一个本机服务和受限工作器，无需为每个人再开模拟器，也无需为目录里的每个职业启动进程。这是可复现的演示布局，不是经过测量的最低内存配置承诺。

启动前可在被忽略的`.env`中限制同时进行的模型调用：

```dotenv
AA_IM_WORKER_SLOTS=8
AA_IM_MODEL_CONCURRENCY=1
```

办公服务启动后，在另一个终端执行：

```bash
python scripts/demo_office_company.py
```

脚本复用本机owner，新建另外四位虚构人类账号、三位职业Agent、任职组织和共同群聊。演示Agent每轮最多3步、每5分钟主动复核；本机账号保存在已忽略的`data/office/demo-company.json`，脚本不会启动模拟器。降低模型并发会降低吞吐；只体验界面时可对launcher使用`--no-worker`。

[真实模型验收](docs/equal_rights/2026-09-06/REAL_COMPANY_MODEL_1546.md)记录三位独立Agent真实提交8个动作，并由独立人类账号读回核对。这份证据与五端UI、长期运行及性能验证分别记录。

## 当前边界与愿景

这是 **0.6 原生办公预览**。Flutter共用客户端面向macOS、Windows、iOS、Android、Web。已有账号会话、内部邮箱、考勤/补卡/审批、个人设置、会议日历、API/MCP/A2A和企业管理，本轮继续补齐职业与任职组织、真实行动、单文档协作和全局搜索。获授权的人与Agent均可管理企业；应用范围策略与资源自身的访问规则分别生效。

OIDC企业登录协议、提供方发现、身份映射及一次性兑换已经实现，并用受控提供方验证；本轮尚未接入真实企业issuer。没有配置提供方时界面不会显示模拟登录入口。

当前仍是单工作空间，组织目录不代表多租户隔离，owner/admin/member固定角色不代表完整自定义管理权限矩阵。推送、外部邮箱投递、地理围栏、大规模音视频、分布式工作器、全量企业安全管理和真实硬件连接仍有明确差距。不能宣称已全量1:1或已超过飞书；参考观察、代码能力和实际验收以[实看对照](docs/equal_rights/2026-09-06/FEISHU_LIVE_DEEP_COMPARISON_1530.md)、[前端实施记录](docs/equal_rights/2026-09-06/STAGE_3_FRONTEND_IMPLEMENTATION_1538.md)及发布台账分别说明。

[新的 equal_rights 版本文档](docs/equal_rights/README.md) 包含产品定义、架构、API、验证证据、提交时间和路线图；[历史 evolve 文档](docs/evolve/README.md) 保持原样，明确区分两个阶段。
